Infrastructure sécurisée multi-sites avec pfSense

📌 Gérer le patrimoine informatique

Contexte : Mise en place d'une infrastructure réseau multi-sites simulant une entreprise disposant de deux agences (Paris et Lyon).


Objectifs :

  • Segmenter le réseau avec des VLAN.
  • Sécuriser les échanges entre les différents sites.
  • Déployer un Active Directory multi-sites.
  • Centraliser l'authentification via LDAP.

Réalisations techniques :

  • Configuration des VLAN Paris et Lyon sur pfSense.
  • Mise en place des règles de pare-feu inter-sites.
  • Déploiement de deux contrôleurs de domaine Active Directory.
  • Configuration de Active Directory Sites & Services.
  • Installation et configuration de GLPI avec authentification LDAP.
  • Virtualisation complète de l'infrastructure sous Proxmox.

Compétences mobilisées :

  • Administration système et réseau.
  • Sécurisation des infrastructures.
  • Virtualisation et segmentation réseau.
  • Gestion des utilisateurs et annuaire LDAP.
pfSense Proxmox Active Directory GLPI LDAP VLAN
✅ Résultat obtenu Les deux sites communiquent via les règles pfSense, les utilisateurs s'authentifient sur le domaine depuis les deux agences et GLPI remonte bien les comptes via LDAP. L'infrastructure est entièrement virtualisée sous Proxmox.

Architecture réseau NAT — DMZ — VLAN avec pfSense

📌 Mettre à disposition des utilisateurs un service informatique

Contexte : Création d'une infrastructure réseau sécurisée avec segmentation des flux et exposition contrôlée d'un serveur web.


Objectifs :

  • Mettre en place une DMZ sécurisée.
  • Segmenter les différents réseaux avec des VLAN.
  • Configurer des règles NAT et firewall.
  • Publier un serveur web vers l'extérieur.

Réalisations techniques :

  • Création des réseaux LAN (10.101.0.0/24), DMZ (10.102.0.0/24) et SERVEURS (10.103.0.0/24).
  • Configuration DHCP et adressage IP sur pfSense.
  • Mise en place de règles de filtrage : LAN → DMZ HTTP autorisé, DMZ → LAN bloqué.
  • Création d'un serveur web Apache2 dans la DMZ (Ubuntu Server 24.04).
  • Configuration du NAT Port Forward : WAN:8080 → DMZ:80.
  • Tests de connectivité et validation de la segmentation des flux.
pfSense 2.7.2 NAT DMZ VLAN Apache2 Ubuntu Server Proxmox
✅ Résultat obtenu Le serveur Apache en DMZ est accessible depuis l'extérieur via http://IP_WAN:8080. La DMZ ne peut pas joindre le LAN (règle Block validée). Le PC-LAN accède bien au serveur web en DMZ sur le port 80.

Plan de Continuité & Reprise d'Activité (PCA/PRA)

📌 Assurer la continuité de service

Contexte : Déploiement d'une infrastructure virtuelle complète sous Proxmox pour mettre en œuvre un Plan de Continuité d'Activité (PCA) et un Plan de Reprise d'Activité (PRA) avec Veeam Backup & Replication.


Objectifs :

  • Déployer une infrastructure multi-VMs représentative d'un SI d'entreprise.
  • Configurer des sauvegardes automatisées des machines virtuelles.
  • Tester la restauration complète après un incident simulé.
  • Identifier les limites d'une architecture mono-serveur physique.

Réalisations techniques :

  • Création de 4 VMs : SRV-AD, SRV-VEEAM, SRV-WEB et Client-test sur Proxmox.
  • Plan d'adressage IP réseau 172.16.13.0/24 avec IP statiques par rôle.
  • Configuration de SRV-AD : rôles AD DS, DNS et DHCP, promotion en contrôleur de domaine (tp.local).
  • Étendue DHCP : plage 172.16.13.100–150, passerelle et DNS configurés.
  • Intégration du Client-test au domaine, vérification par ping et connexion.
  • Installation Apache2 sur SRV-WEB, page personnalisée validée depuis le client.
  • Adaptation en environnement personnel : réseau 192.168.18.0/24, Apache2 fonctionnel.
  • Procédure Veeam B&R 13 documentée : installation, job de sauvegarde VM, restauration complète.
Proxmox VE Windows Server 2022 Active Directory DNS / DHCP Veeam B&R 13 Apache2 PCA / PRA
✅ Résultat obtenu Infrastructure AD opérationnelle : domaine tp.local fonctionnel, Client-test intégré, Apache2 accessible. L'installation de Veeam n'a pas abouti en environnement école (espace disque insuffisant et pas d'accès Internet) — la procédure de sauvegarde et restauration a été intégralement documentée et réalisée en environnement personnel.
