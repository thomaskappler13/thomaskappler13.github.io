Installation pfSense — NAT · DMZ · VLAN

Déploiement d'un pare-feu avec segmentation réseau complète sous Proxmox

E5 — 01

Contexte : Mise en place d'une infrastructure réseau segmentée sous Proxmox avec pfSense comme pare-feu central. L'architecture repose sur trois VLANs distincts (LAN, DMZ, Serveurs) reliés via un bridge VLAN-aware, avec exposition sécurisée d'un serveur web Apache en DMZ.

Procédures techniques :

  • Création d'un bridge vmbr100 VLAN-aware sur Proxmox et ajout de trois interfaces virtuelles (VLAN 101 LAN · VLAN 102 DMZ · VLAN 103 SERV)
  • Installation et configuration de pfSense 2.7.2 : attribution des interfaces WAN (em0), LAN (em1), OPT1/DMZ (em2), OPT2/SERV (em3)
  • Configuration IP statique de chaque interface : LAN 10.101.0.1/24, DMZ 10.102.0.1/24, SERV 10.103.0.1/24
  • Activation du serveur DHCP sur le VLAN LAN (plage 10.101.0.50–100)
  • Règles de filtrage pare-feu : LAN → DMZ HTTP autorisé, DMZ → LAN bloqué, DMZ → Internet autorisé
  • Redirection NAT Port Forward : WAN:8080 → 10.102.0.10:80 pour exposer le serveur Apache depuis l'extérieur
  • Installation et validation d'Apache2 sur la VM WEB-DMZ (Ubuntu Server 24.04, IP 10.102.0.10)
  • Tests de connectivité : ping 8.8.8.8 depuis PC-LAN, accès http://10.102.0.10 depuis LAN, accès http://IP_WAN:8080 depuis le PC physique
pfSense 2.7.2 Proxmox VE VLAN NAT / Port Forward Apache2 Ubuntu Server 24.04 Pare-feu DMZ

Mise en place d'un plan de sauvegarde PCA/PRA

Infrastructure virtuelle Proxmox avec Veeam Backup & Replication

E5 — 02

Contexte : Déploiement d'une infrastructure virtuelle complète sous Proxmox pour mettre en œuvre un Plan de Continuité d'Activité (PCA) et un Plan de Reprise d'Activité (PRA). L'objectif est de configurer des sauvegardes automatisées de VMs et de tester la restauration complète après incident.

Procédures techniques :

  • Création de 4 VMs sur Proxmox : SRV-AD (Windows Server 2022), SRV-VEEAM (Windows Server 2022), SRV-WEB (Linux Ubuntu), Client-test (Windows 10)
  • Plan d'adressage IP réseau 172.16.13.0/24 : SRV-AD .10, SRV-VEEAM .20, SRV-WEB .30, Client en DHCP
  • Configuration de SRV-AD : rôles AD DS, DNS et DHCP — promotion en contrôleur de domaine (forêt tp.local)
  • Création de l'étendue DHCP : plage 172.16.13.100–150, passerelle .1, DNS .10
  • Intégration du Client-test au domaine tp.local et vérification (ping srv-ad, ping tp.local)
  • Installation d'Apache2 sur SRV-WEB, personnalisation de la page index.html, vérification depuis le client
  • Adaptation en environnement personnel : réseau 192.168.18.0/24, installation et validation complète d'Apache2
  • Procédure Veeam Backup & Replication 13 : installation, configuration d'un job de sauvegarde VM, restauration complète — limites documentées
Proxmox VE Windows Server 2022 Active Directory DNS / DHCP Veeam B&R 13 Apache2 PCA / PRA

Configuration pfSense pour Active Directory Multi-sites

Interconnexion de sites distants avec authentification centralisée

E5 — 03

Contexte : Configuration d'un environnement pfSense pour interconnecter plusieurs sites distants et permettre l'authentification via un Active Directory centralisé. Mise en place du routage inter-sites et de la résolution DNS nécessaire au bon fonctionnement du domaine.

Procédures techniques :

  • Configuration des interfaces WAN et LAN de pfSense pour chaque site
  • Paramétrage du routage statique inter-sites pour assurer la connectivité entre les réseaux
  • Configuration du DNS Resolver de pfSense pour la résolution du domaine Active Directory
  • Mise en place des règles pare-feu autorisant le trafic AD (LDAP, Kerberos, DNS, RPC)
  • Intégration des postes clients distants au domaine via pfSense comme passerelle
  • Vérification de l'authentification et des GPO appliquées sur les sites distants
